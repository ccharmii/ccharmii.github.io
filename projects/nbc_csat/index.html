2025. 12 – 2026. 01 (3주)

[프로젝트 요약]

  • 목적: 제한된 컴퓨팅 리소스 환경에서 4B 규모 추론 모델에 Test time scailing을 적용해 성능 극대화
  • 성과: 최종 Macro F1 Score 0.6701을 기록하며 4B Reasoning 모델 단순 추론 대비 약 11% 성능 향상을 달성했으며, 특히 RAFT 방법론 적용을 통해 단순 RAG 대비 0.13의 유의미한 점수 개선을 이끌어냄

1. Baseline 리팩토링

  • 문제 인식: 이전 프로젝트 진행 시 Baseline 코드의 구조적 결함으로 인해 코드 병합 및 새로운 방법론 적용 시 불필요한 시간이 과도하게 낭비됨
  • 해결 방안:
    • 추상화 설계: Trainer, Preprocessor, Model Loader 등을 추상 클래스로 정의하여 모듈화
    • YAML 기반 Config 인자 변경만으로 새로운 방법론을 즉시 테스트할 수 있는 환경을 구축하여 실험 속도 가속화

2. Test Time Scailing을 통한 모델 지식 분류 및 최적화

  • 문제 인식: 모델이 알고 있는 지식과 모르는 지식 (RAG가 필요한 문제) 을 분리하면 성능이 오름. 단순히 모든 문제에 대해서 RAG를 진행하기보다 LLM As a Judge로 RAG가 필요한 문제에만 RAG를 적용하면 성능이 오름
  • 해결 방안: Test 단계의 Sampling을 통해 모델이 알고 있는 지식과 헷갈리는 지식을 나눠 처리

• 지식 상태 분류: 동일 문항에 대해 5회 샘플링을 진행하여 답변의 일관성을 측정

  • 확신(Agreement == 1): 모든 샘플이 동일한 답변을 내놓을 경우 모델의 내재된 지식으로 판단하여 즉시 정답 반환
  • 혼란(Agreement < 1): 답변이 엇갈릴 경우 모델이 헷갈리는 지식으로 판단하여 보완 단계 진입

• LLM as a Judge 기반 검증: 혼란 상태의 문항에 대해 Reasoning 분석을 통해 일관성 판단

• 선택적 RAG 및 RAFT 활용: 검증 점수가 낮은 문항에 한해서만 RAG 컨텍스트를 제공하고, 문서 선별 능력이 강화된 RAFT 모델로 최종 추론을 수행

• 결과: 4B Reasoning 모델 단순 추론(0.6027) 대비 최종 Macro F1 0.6701 달성

3. RAFT 구현 및 고도화

  • 문제 인식: 모든 문항에 일괄적으로 RAG를 적용했을 때, 문제와 무관한 문서가 노이즈로 작용하여 오히려 성능이 하락(0.6027 → 0.5365)하는 문제 발견
  • 해결 방안: 모델이 문서를 선별적으로 활용하도록 학습시키는 RAFT(Retrieval-Augmented Fine-Tuning)를 도입
  • 상위 모델(30B)의 Reasoning Trace를 추출하여 학습 데이터 생성 및 Knowledge Distillation 효과 유도
  • 모델의 오답(이중 추론 실패, 지문 과의존 등) 패턴을 분석하여 Context Engineering 진행
구분 특징
정답 샘플 문제 유형을 먼저 선언하는 명확한 reasoning
None 샘플 추론이 너무 길어 정답 출력 실패
오답 원인 이중 추론에 취약, 지문 과의존, 못 찾으면 5 출력
