[프로젝트 요약]

  • 목적: 사용자의 도메인 지식 수준과 가용 시간을 반영하여, 목표 논문을 이해하기 위해 반드시 알아야 할 개념들을 그래프 형태로 제공하고 최적의 학습 경로를 설계하는 Multi Agent 기반 웹서비스 구현
  • 성과:
    • Graph Database 기반의 지식 추출을 통해 LLM의 Hallucination을 억제하고 학습 경로의 해석 가능성 확보
    • 사용자 설문 결과, 서비스 제시 키워드와 필수 선수 개념 간 일치도 약 60% 달성 및 75% 이상의 긍정적 피드백 수렴

1. 기존 문제점 분석

  • 최신 AI 논문 학습 수요는 높아졌지만, 선수 지식과 선행 논문에 대한 이해 부족으로 인해 높은 진입장벽 존재
  • 설문 결과 인사이트: 네이버 부스트캠프 교육생 및 멘토 33명 대상 설문 결과, 73%가 선수 개념 보조 자료를, 85%가 한눈에 볼 수 있는 개념도를 필요로 함

2. Graph Database 설계 및 구축

  • 문제 인식: 일반적인 LLM만으로 선수 개념을 생성할 경우, 정보 일관성이 낮고 실제 존재하지 않는 개념이 생성되는 Hallucination 발생 가능성 존재
  • 해결 방안:
    • Semantic Scholar, Wikipedia 데이터를 활용하여 논문-개념 간 관계를 정의한 Neo4j 기반 Graph Database 구축
    • Paper, Keyword 노드와 PREREQ, IN, ABOUT, REF_BY 관계를 중심으로 핵심 그래프 구조 설계
관계 유형 (Type) 구조 (Direction) 의미 (Description)
PREREQ 키워드 A → 키워드 B A가 B의 선수 지식임 (B를 알려면 A를 알아야 함)
IN 키워드 A → 논문 논문을 이해하기 위한 선수 개념이 A임
ABOUT 논문 → 키워드 A 논문의 주요 개념이 A임 (A를 주되게 제안함)
REF_BY 논문 A → 논문 B 논문 B가 논문 A를 참고함
→ 선수 개념 관련 서베이 논문 리뷰 보기

결과: 구조화된 지식 데이터를 바탕으로 사용자에게 근거 있는 학습 경로를 시각화하여 제공할 수 있는 기반 마련

3. Agent 구현 및 Context Engineering

  • 문제 인식: 과도한 선수 개념 포함으로 인한 학습 효율 저하 및 개인화 정보(수준, 시간 등) 미반영 한계
  • 해결 방안:
    • 순환 엣지 제거 및 입력 구조 표준화 전처리 수행
    • 사용자 수준, 기존 지식 반영, 학습 목적, 목표 소요 시간 등을 반영한 Keyword Graph Agent 구현 및 Context Engineering 수행

4. Web Search Tools 디벨롭

  • 문제 인식: 단일 툴 구조의 한계(자료 다각화 부족), API 호출 과부하, 중복 제거 시 검색 결과 유실 문제
  • 해결 방안:
    • Web(Serper)·Video(YouTube)·Paper(Semantic Scholar)를 통합하는 파이프라인 구축
    • 사용자 Preference에 따른 동적 max_results 조합 로직 설계 (Rule-based)
    • 데이터 기반 Reranking: Score = (Quality * 1.5) + Preference Weight 적용 및 상위 3개 자료 추출
  • 결과:
    • 검색 결과 유실률 0% 달성 및 에이전트 호출 비용/시간 약 60~70% 절감
    • 사용자 선호 타입 가중치 반영을 통해 맞춤형 자료 추천 기능 강화
