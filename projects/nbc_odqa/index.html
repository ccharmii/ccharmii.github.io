Role: EDA 및 검증 전략 수립, Baseline 코드 리팩토링, monoQA 적용
2025. 11 (2주)

GitHub Link Wrap-up Report Link

[프로젝트 요약]

  • 목적: Wikipedia 기반 Open-Domain Question Answering(ODQA) 파이프라인 구현 및 정답 예측
  • 성과: 최종 1위 달성 (Private EM 74.17%)

1. 검증 데이터 재구축

  • 문제 인식: 초기 실험 시 Validation EM과 리더보드 점수 간의 괴리가 커 실험의 신뢰도가 낮음
    • BM25 유사도 분석 결과, 기존 Validation 셋이 Test 셋보다 Train 셋과 너무 유사한 분포를 보임 (Train-Val 유사도 9.74 vs Test-Val 유사도 4.80)
  • 해결 방안: Test 데이터셋의 유사도 분포와 일치하도록 Validation 데이터셋을 재구축
  • 결과: Val EM과 리더보드 점수 차이를 15%p에서 9.6%p로 약 5.4%p 개선하며 실험의 신뢰도 확보

2. SOTA 방법론 monoQA 구현 및 적용

  • 문제 인식: 단일 Extraction 모델만으로는 문서 내에 정답이 존재하더라도 문맥적 이해 부족으로 답을 찾지 못하는 한계 존재
  • 해결 방안: Reranking과 Answer Extraction을 통합한 Multi-task Learning 모델 도입
    • KorQuAD 2.0 1위 모델인 EXAONE 구조를 벤치마킹하여 Reranker와 Reader를 통합한 monoQA 구조 구현
    • Generative 모델을 기반으로 Extraction 모델이 놓치는 문맥적 정답을 생성하는 강점 확보

3. 결과 분석 및 앙상블

  • 모델별 성능 비교: Generative 기반 monoQA가 EM은 낮지만 F1 Score가 높은 것을 확인
    • 모델 이름 EM (%) F1 (%)
      monoQA (Qwen3-4B LoRA) 65.00 69.87
      monoQA (T5 finetuning) 57.50 63.56
  • 최종 전략: monoQA에 0.130의 가중치를 부여한 Casting Vote로 활용하여 앙상블 모델의 다양성과 정밀도 동시 확보
